# Demo Access

A live instance of this project is running at:

**https://it-helpdesk-1v7u.vercel.app**

The database is seeded with synthetic demo data (tickets, assets, users, requests).
Sign in with any of the accounts below — every role lands on a different screen,
so you can walk the full approval flow.

| Role     | Email                  | Password |
| -------- | ---------------------- | -------- |
| Admin    | `admin1@itsm.com`      | `123456` |
| Manager  | `manager1@itsm.com`    | `123456` |
| Agent    | `agent1@itsm.com`      | `123456` |
| Employee | `employee1@company.com`| `123456` |

There are 5 admins, 5 managers, 10 agents and 30 employees seeded
(`admin2@itsm.com`, `agent2@itsm.com`, `employee2@company.com`, and so on).

## What to look at

1. **Sign in as Admin** → dashboard with ticket status breakdown, weekly activity
   chart, pending approvals and recent tickets.
2. **Asset Requests** → raise a request, then approve it as Manager
   (MANAGER_APPROVED) and again as Admin (ADMIN_APPROVED) to see the two-stage
   approval chain and the asset allocation it triggers.
3. **Tickets** → create a ticket at `critical` / `high` / `medium` / `low` priority
   and watch the SLA deadline and status (on track → at risk → breached) update
   from the priority. Add internal-only comments as an agent.
4. **Sign in as Employee** → the same login routes to `/tickets`; `/dashboard`,
   `/assets` and `/users` are blocked by route middleware, which demonstrates the
   role-based access control.
5. **Assets** → filter by status (AVAILABLE / ALLOCATED / IN_REPAIR / RETIRED) and
   inspect allocation history per asset.

## Notes

- These are throwaway demo credentials on a public deployment. Anyone who reads
  this file can sign in, so do not treat the demo data as anything but scratch
  space, and do not reuse these passwords anywhere else.
- All data is synthetic and generated by `prisma/seed/`. No real user or asset
  information is present.
